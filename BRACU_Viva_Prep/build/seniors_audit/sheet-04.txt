B36: Divide and Conquer
C36: Divide and Conquer: Solves a problem by breaking it into independent subproblems (or treats them as independent). No caching is done, so overlapping subproblems are recomputed multiple times, leading to inefficiency in cases where subproblems overlap.

B38: Dynamic Programming
C38: Dynamic Programming: Leverages overlapping substructure by solving each subproblem only once and caching (memoization or tabulation) the results for future reuse. This eliminates redundant computations and makes the approach efficient.

B46: Hash Table 
C46: If we know all the datapoints in advance, then we can theoratically design a perfect hash function
D46: Load Factor: (Total number of stored items/array size)

Simple Uniform Hashing: We shall assume that any given element is equally likely to hash into any of the m slots, independently of where any other element has hashed to.

Open Addressing: All elements occupy the hashtable itself. No extra linked list branches or anything like that. Probing is done for open addressing

Probing: The act of searching for an empty space in the hastable for insertion

Deletion in Open Addressing: When we delete a key, we mark it as deleted instead of NIL. Otherwise when searching we might not find the element we were suppose to, eventhough it exists.
Chaining is more commonly used when frequent deletion in hash table is to be done

B50: Hash Functions
C50: Hash Function has two parts: Hash code and Compression Function.
The goal of a hash function is to disperse the keys in a random way so that less collision occurs

Hash Code: Transforms the key into an integer
Compression Function: Transforms the integers into a int ranged form 0 to N-1
D50: Primary Clustering: When a group of elements is hashed to adjacent slots, creating long clusters of occupied slots.

Secondary Clustering: Secondary clustering occurs when keys that hash to the same initial position follow the same probe sequence and end up clustering together. 
B52: Regular Hashing vs Uniform Hashing
C52: Regular Hashing: Practical implementation of hashing, distributions may not be perfect or uniform

Uniform hashing: All positions are equally likely to be hashed for the given key
B54: Double Hashing
C54: Double hashing uses a hash function of the form
	h(k, i) = ( h1(k) + ih2(k) ) mod m
where both h1 and h2 are auxiliary hash functions.
The value h2(k) must be relatively prime to the hash-table size m for the entire hash table to be searched. 
A convenient way to ensure this condition is to let m be a power of 2 and to design h2 so that it always produces an odd number. 
Another way is to let m be prime and to design h2 so that it always returns a positive integer less than m.
